# 🏫 校园墙

校园综合交流平台，支持表白、投票、聊天等功能。

---

## 📋 功能清单

### 👤 账号系统
| 功能 | 说明 |
|------|------|
| 注册 | 用户名 + 密码 + 昵称 + 真实姓名 |
| 登录 | JWT 认证，7天有效期 |
| 修改密码 | 需验证旧密码 |
| 注销账号 | 阅读须知 + 10秒等待，数据永久删除 |
| 个人资料 | 昵称、真实姓名、性别、自我介绍、班级、毕业信息 |
| 联系方式 | QQ、微信、微博、B站，可选择是否对外显示 |
| 头像上传 | 支持图片上传，自动压缩 |

### 📝 帖子系统
| 功能 | 说明 |
|------|------|
| 发帖 | 支持选择分类（吐槽、分享、求助、讨论、其他）或自定义分类 |
| 匿名发帖 | 不保存用户信息，仅保留IP可追溯 |
| 点赞 | 每人每帖一次 |
| 评论 | 支持文字评论 |
| 搜索 | 按帖子内容搜索 |
| 分类筛选 | 左侧分类栏，支持按话题筛选 |
| 删除 | 作者、管理员、超级管理员可删除 |
| 发帖草稿 | 当前标签页自动保存，按账号和校园墙隔离；刷新或返回可恢复，发布成功或退出登录后清除 |

草稿包含文字、分类、匿名/Markdown 选项和已上传的图片链接，可手动确认清除；不会保存原始图片文件。草稿使用 sessionStorage，不在不同浏览器或标签页之间同步。存储被禁用或已满时会提示，并继续允许编辑和发布。

### 💌 表白信
| 功能 | 说明 |
|------|------|
| 撰写 | 支持标题 + Markdown 正文；可选择允许收信人回复，默认关闭 |
| 指定收件人 | 按真实姓名搜索（遵循对方的搜索隐私设置） |
| 匿名/实名 | 可选择是否匿名发送，匿名回复沿用原信身份保护 |
| 直接表白 | 不写信，选定收信人后发送由服务端生成的实名表白提示 |
| 身份申请 | 匿名信收件人可确认发送身份查看申请，附言支持 Markdown；仅经写信人同意才展示其昵称、头像和主页 |
| 表白统计 | 在综合统计页查看当前校园墙收到的匿名、非匿名及总表白数量，并查看详情；回复和身份申请不计数 |

### 📊 投票系统
| 功能 | 说明 |
|------|------|
| 创建投票 | 2-10个选项，支持自定义 |
| 投票 | 每人每投票一次，需二次确认 |
| 截止时间 | 可设置投票截止时间 |
| 匿名投票 | 可选择匿名创建 |
| 结果展示 | 实时显示投票数和百分比 |

### 💬 聊天系统
| 功能 | 说明 |
|------|------|
| 好友列表 | 按名字/时间排序 |
| 私聊 | 最近会话、消息引用与定位、历史分页和会话搜索 |
| 表情 | 48个常用表情 |
| 消息操作 | 复制、仅自己删除、5分钟内撤回；失败发送用同一请求编号安全重试 |
| 聊天偏好 | 发送快捷键、消息密度、时间显示和刷新间隔 |
| 清空记录 | 仅隐藏自己的聊天记录，保留对方视图 |

### ⚙️ 设置中心

设置按账号隐私、外观、阅读、聊天、通知、导航和数据分组，支持跨分类搜索、自动保存状态与失败重试。可预览后导入偏好、导出偏好，或按分类恢复默认；这些操作不会重置账号隐私、密码或消息。主题支持跟随系统、亮色和暗色，可单独关闭壁纸。液态玻璃效果默认启用，可在“设置 → 外观”关闭；关闭模糊或开启高对比度时自动降低透明效果。按钮、卡片和弹层增加轻量过渡，遵循系统及站内减少动画偏好。手机界面支持安全区、窄屏分类切换和聊天软键盘高度适配。

### 📈 统计信息

点击头像菜单中的“统计信息”，可查看注册时间、使用天数、已加入的有效校园墙数、好友数、实名发帖数、评论数、收藏数与参与投票数。账号概览汇总本人的跨墙数据，无需先加入校园墙；匿名帖子不关联作者，因此不计入实名发帖数。表白统计是单独区域，按当前校园墙展示，保留信件详情。

## 🚀 运行、配置与验证

需要 **Node.js >=22.12.0** 和 npm。安装使用已提交的两个 package-lock.json，每次都执行 npm ci 并重新构建前端，已有 node_modules 或 dist 不会跳过更新。后端使用 sharp 进行真实图片解码和重编码，必须在目标操作系统/CPU 上安装其原生依赖；不要跨平台复制 node_modules，也不要禁用 optional 依赖。

### Linux 本地运行

~~~bash
# 安装锁定依赖、重建前端、前台启动；Ctrl+C 停止
bash deploy.sh
bash deploy.sh --port 8080

# 只安装/构建，不启动应用
bash deploy.sh --prepare-only
# 只检查现有 Node、sharp 原生编码/解码与构建是否存在，不安装或启动
bash deploy.sh --check
~~~

默认只监听 127.0.0.1。首次启动后在本机完成初始化向导，系统没有默认管理员账号。需要局域网直连时，可在完成初始化后显式设置 HOST=0.0.0.0；公网运行应使用 HTTPS 与反向代理，生产模板及运维步骤见 [部署说明](deploy/README.md)。

### Windows

~~~bat
REM 安装锁定依赖、重建并打开后端窗口
deploy.bat
deploy.bat --port 8080
REM 开发模式：后端 3000 + 仅本机 Vite 5173
start.bat
REM 默认端口被其他程序占用时，可明确指定新端口，代理自动保持一致
start.bat --port 3001 --client-port 5174
REM 停止指定端口上经验证属于本项目的后端和开发前端
stop.bat --port 3001 --client-port 5174
REM 未指定 --client-port 时仅停止后端
stop.bat --port 8080
~~~

Windows 入口使用随系统提供的 PowerShell、NetTCPIP 与 CIM。启动前检查两个端口，Vite 不会自动跳到其他端口；只有后端数据库健康、前端页面和 API 代理全部就绪才报告成功。启动失败会清理本次创建的进程。停止脚本先核对所有目标端口、Node 可执行程序和本项目绝对入口路径，再执行停止；遇到其他项目进程会拒绝操作。开发前端也可在自己的窗口按 Ctrl+C 停止。Windows 进程终止可能中断未落盘写入，维护前请备份数据。

同一项目的旧进程若仍占用原生依赖，即使切换端口也不能重装。启动脚本会在执行 `npm ci` 前报告占用的进程和监听端口；请先在原终端按 Ctrl+C 关闭旧实例，再重试。

### 配置与持久化

| 变量 | 默认值 / 用途 |
|------|--------------|
| PORT | 3000；后端监听端口，范围 1–65535 |
| VITE_BACKEND_PORT | 3000；直接运行 Vite 时的后端代理端口；start.bat 由 --port 自动设置 |
| VITE_PORT | 5173；直接运行 Vite 时的前端端口；start.bat 由 --client-port 自动设置 |
| HOST | 启动脚本默认 127.0.0.1；显式设置 0.0.0.0 才开放局域网直连 |
| DATA_DIR | server 目录；data.db、.jwt_secret、uploads、backups 与 wallpaper-cache 均位于该数据根 |
| JWT_SECRET | 可选，至少 16 字符；不设置时自动生成并持久保存 .jwt_secret |
| TRUST_PROXY | 默认不信任；随附 Nginx 模板只设置为 1，并由代理覆盖客户端转发头 |
| ALLOWED_ORIGINS | 可选，逗号分隔的额外允许来源；同源部署无需设置 |
| UPLOAD_MAX_TOTAL_MB | 默认 2048，上传总配额 |
| UPLOAD_MAX_USER_MB_PER_HOUR | 默认 50，每用户每小时上传额度 |

后端直接运行时通过 shell 设置环境变量；应用与本地启动脚本不会自动读取后端 .env。Vite 的 VITE_* 配置可通过环境变量或 client/.env.local 设置。systemd 模板会读取 server/.env，具体格式和 DATA_DIR 可写路径由部署安装器校验。相对 DATA_DIR 按后端工作目录解析，建议使用绝对路径。改变数据根不会自动搬迁旧数据；请停服务后一起迁移数据库、密钥、上传与备份，再更新配置。常规部署固定 KEEP_DB=1，避免误触发删库重建。

### 壁纸与外观

在“设置 → 外观”选择“必应每日壁纸”或“本地随机壁纸”，来源随账号保存。必应图片由后端获取并保存到 DATA_DIR/wallpaper-cache，浏览器只请求本站资源；归档缓存一小时，相同图片复用缓存与 ETag。上游超时或图片无效时回退到 rele，网络中断时保留已经显示的壁纸。关闭背景、毛玻璃、高对比度和减少动效选项继续生效。

### 检查

回归测试使用 Node.js 内置测试运行器，无需额外安装测试框架。在项目根目录执行以下命令；后端测试使用临时数据目录和本机随机端口，不读取或修改现有站点数据库。

~~~bash
# 运行前端逻辑、后端接口与持久化、移动 SDK 的全部回归测试
node --test
# 也可分别运行前后端测试
npm --prefix server test
npm --prefix client test
# 编译前端并检查公共 API 操作清单与 OpenAPI 保持一致
npm --prefix client run build
node sdk/generate-v1-operations.cjs --check
# 依赖审计需要连接 npm registry
(cd server && npm run audit:security)
(cd client && npm run audit:security)
# 服务启动后检查数据库健康；默认后端端口为 3000
curl --fail --max-time 5 http://127.0.0.1:3000/api/health
~~~

/api/health 会实际查询数据库；只看到静态首页返回 200 不能证明后端健康。

## 📌 首次设置

系统**不预置任何默认账号**。首次启动后访问站点首页，会进入初始化向导：

1. 创建超级管理员账号（用户名 + 密码 + 昵称）
2. 创建第一个校园墙

完成后即可登录使用。请为超级管理员设置强密码 —— 它拥有全部管理权限；
注册面向所有人开放（受登录限流保护），如需限制成员，请使用「进墙审批」。

如果数据目录中没有 `data.db`，也可以在本机打开初始化页，点击 **进入一次性测试**。系统会创建临时普通用户和测试墙，无需设置密码。测试不支持图片上传，数据库仅保存在内存中。停止或重启后端会清除测试数据；只关闭网页不会清除。重启后可重新测试或正式初始化。已有数据库或经反向代理访问时，不提供此入口。

## 📡 API 接口

API 规范覆盖 **145 个版本化 API 操作与 10 个看板内部操作**，公共 SDK 提供 144 个可调用操作。实现说明见 [后端优化说明](docs/BACKEND-OPTIMIZATION.md)。

未来移动客户端使用 `/api/v1`，现有网页使用的 `/api` 保持兼容。v1 JSON 响应统一包含 `data`、`error` 和 `meta`，继续使用 Bearer JWT、`X-Wall-Id` 及原有权限/限流。开放协议不代表匿名开放用户数据，浏览器跨域来源仍需配置 `ALLOWED_ORIGINS`。

- `GET /api/v1/capabilities`：版本、认证方式、分页和容量限制。
- `GET /api/v1/openapi.json`：原始 OpenAPI 3.0.3 文档（不套 JSON 包络）。
- [移动 API 使用指南](docs/MOBILE-API.md)、[OpenAPI 契约](docs/openapi.json)、[便携 Fetch SDK](sdk/mobile-client.mjs) 与 [TypeScript 声明](sdk/mobile-client.d.ts)。
- 私聊支持 `before`/`after`/`around_id` 游标、`q` 搜索、`mark_read=0` 纯读和 `client_message_id` 幂等发送。设置 schema 与分类重置分别为 `/auth/prefs/schema` 和 `/auth/prefs/reset`。
