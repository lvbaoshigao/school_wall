日期：2026-11-20。基线：32507ff。所有验证使用合成数据、内存数据库或临时 DATA_DIR；没有部署或修改真实用户数据库。

## 导航

顶栏采用居中长药丸壳，桌面最大宽度 1180px、高 64px，顶部间距 8px、圆角 999px。沿用校园墙主题，支持亮暗、高对比度、降低透明度与减少动效。小屏保留左右留白，使用现有移动面板容纳全部导航；下拉菜单不会被药丸边缘裁剪。安全区与聊天可视高度使用同一组变量。

### 视觉反馈修正

恢复原有本地图库壁纸，取消将原图压至 22% 后再覆盖 80–95% 遮罩的叠加；页面底色改为中性亮灰/深灰。内容与药丸的常规间距为桌面 36px、移动 24px，主页左右栏各 210px，中间阅读宽度保持不变。卡片悬浮继续使用足够不透明的表面。桌面两翼等宽、中心搜索居中，主入口与“更多”分组的按钮间距为 6px、组间距 16px。菜单进出改为独立 scale 与 opacity，尊重减少动效，并保留键盘焦点逻辑。

[恢复壁纸后的页面预览](previews/wallpaper-restored-light.png)。本轮实际浏览器同时验证了原图加载、亮暗中性背景、壁纸开关、强调色切换、等宽侧栏、菜单真实缩放事件，以及 320/375/768/1024px 无横向溢出；没有将构建中的中间截图作为最终结果。

### 默认毛玻璃

药丸、卡片与导航面板现在默认采用半透明底色和真实 backdrop-filter 模糊；外观设置中的“毛玻璃效果”是默认开启的正向开关，关闭后恢复不透明表面。底层沿用原 disable_blur 偏好，账号保存、导入导出、恢复默认与旧客户端保持兼容。已选择关闭的账号不会被强制重置。高对比度、系统减少透明效果及不支持滤镜的浏览器会使用不透明回退。

[默认毛玻璃预览](previews/glass-default-light.png)。真实生产构建浏览器验收覆盖亮暗、默认开启、关闭/开启与刷新持久化、手机开关效果和辅助偏好回退；常规前端回归 143 项通过，7 个需本机实例的浏览器入口默认跳过，本轮毛玻璃入口另行完整通过。构建同时保留标准与 WebKit 滤镜属性，避免仅声明前缀却实际未模糊。

## 可复核的后台改进

以下是同一组合成 100 会话数据的 SQL 调用次数对照，包含测试夹具的鉴权查询，不是线上耗时或 QPS 承诺。优化后的调用数由回归用例守护上界；超过批处理分块容量时会按块增加。

| 路径 | 基线调用次数 | 优化后上界 |
| --- | ---: | ---: |
| 最近私聊摘要 | 803 | 5 |
| 树洞未读 | 403 | 6 |
| 收件箱 | 712 | 7 |
| 树洞会话列表 | 908 | 9 |

消息查询使用批量 JOIN/CTE，引用发送者及墙成员批量读取。权限与树洞访问结果只在当前请求中复用；下一请求仍重新检查角色、deny、封禁、拉黑、接手人和单侧删除。已读或过期封禁发生实际变更时才标记持久化。审批列表也修正为逐墙遵守 deny，与实际审批授权保持一致。

帖子点赞和收藏状态只查询当前响应页的 ID，不再物化用户的全部互动历史。投票列表把逐条选项/本人投票查询改为限定本页的批量查询，显式业务 SQL 从 2N+2 收敛到最多 3 条。原匿名、排序、分页、计数和写事务契约保持兼容。

SQLite 结果转换对 12,000 行只读取一次列名元数据，基线为每行读取一次。保留每次语句独立释放，不缓存 prepared statement，以免数据库 export、迁移、关闭与事务边界导致句柄失效。树洞未读、树洞首条消息和投票选项添加了经 EXPLAIN 验证的索引，减少对应全表扫描或临时排序。书签索引候选因现有多表 JOIN 未稳定选择而撤销，没有将其报告为收益。

限流与首次认证共享当前请求内的有效签名及同步用户快照。后续认证、异步边界后的检查仍实时查询账号状态、token_version 和角色，并实时判定 exp/nbf；缓存同时绑定请求、授权头、数据库和密钥。权限覆盖改为真正使用 req.can 时再加载，失败仍关闭访问。

入口未读计数按类型一次分组；API 规范文本只在文件版本变化时重读和解析，并支持原子替换、损坏/删除后的明确 503。备份下载明确使用 application/octet-stream，用户导出仍为 application/gzip，跨域导出的可观察头与 v1 关联 ID 合并保留。

## API 覆盖的定义与边界

通过隔离子进程启动真实 Express 应用，捕获所有显式注册的方法/路径并展开嵌套路由挂载，逐项与 OpenAPI 比对：

| 范围 | 实际操作 | 规范操作 | 缺失/多余 |
| --- | ---: | ---: | --- |
| /api/v1 对应业务与发现接口 | 144 | 144 | 0 / 0 |
| 看板内部 /dashboard/api/* | 10 | 10 | 0 / 0 |
| 合计 | 154 | 154 | 0 / 0 |

全部 154 个 operationId 唯一，基线 52 个标识保持原名。内部 Cookie/CSRF API 按操作声明根服务器与 x-internal；静态文件和 SPA 页面不是业务 API，隐式 HEAD 与跨域 OPTIONS 不另计。覆盖回归直接读取真实注册，未来增加或删除路由而不更新规范会失败。

移动 SDK 对普通 v1 操作提供按 operationId 的目录入口。10 个看板内部操作及 1 个只用于网页 Cookie 票据交换的桥接操作有明确排除策略；这不改变服务器可用性或授权。旧 convenience helpers 与响应包络保留，原始 OpenAPI 与二进制下载使用专用解析，失败仍保留 HTTP 状态、业务 code/details 和请求 ID。

规范见 [openapi.json](openapi.json)，接入说明见 [MOBILE-API.md](MOBILE-API.md)，SDK 见 [mobile-client.mjs](../sdk/mobile-client.mjs)。

## 验证结果与入口

最终后端回归 268/268 通过；前端常规回归 135 项通过、5 个需要隔离浏览器环境的入口默认跳过；本轮独立药丸导航浏览器统计 60/60 通过。部署兼容回归 22/22 通过。SDK 旧契约与新增全操作目录回归合计 20/20 通过，143 个目录入口均执行了无真实写入的 method/path 分发核验，严格 NodeNext 类型消费也已通过。最终隔离主服务另行走通真实登录、用户信息、投票列表、原始 OpenAPI、由生成目录调用的备份创建及 SQLite 二进制下载。

这些记录区分文档/目录覆盖与真实业务写入验证，不表示把所有危险管理操作在生产执行过。

Chrome 模拟不等于实体 iOS/Android、Safari/Firefox 或人工读屏验收。合成样本的 SQL/元数据计数改善也不等于生产负载下的固定加速倍数；本轮保持 sql.js、原权限和版本兼容策略，没有实施数据库引擎替换或生产部署。
