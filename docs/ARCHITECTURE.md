# 前后端边界与管理数据说明

## 分离检查结论

项目采用两个独立的 npm 工程：Vue/Vite 浏览器应用位于 [client](../client/package.json)，Express JSON API 位于 [server](../server/package.json)。浏览器生产源码不导入后端源码，两端分别安装运行时依赖；少量跨工程契约测试会读取另一端的定义，属于测试时耦合，不是浏览器运行时依赖。保留“后端顺带托管前端构建产物”的兼容方式，但后端运行不再要求存在前端构建。

| 层次 | 职责 | 边界 |
| --- | --- | --- |
| 浏览器应用 | 页面、交互、缓存、展示权限与错误状态 | 不能决定真实授权，不能直接查询数据库 |
| HTTP 路由 | 当前身份、参数验证、业务授权、HTTP 响应 | 不将数据库行或敏感身份原样暴露给页面 |
| 管理概览服务 | 共享统计口径、范围过滤、聚合与权限脱敏 | 不拼接页面、不返回私信正文或匿名作者身份 |
| 独立运维看板 | 无需 Vite 构建的后端管理页面 | 不另外维护统计 SQL 或跳过现有授权 |
| 持久化数据根 | 数据库、密钥、上传、备份与缓存 | 不应放入前端构建或公开静态目录 |

[后端入口](../server/index.js) 负责挂载路由与可选静态托管；[运行配置](../server/config.js) 统一校验端口、监听地址、来源列表和静态托管开关。独立看板与 Vue 管理区共用管理概览服务，避免统计口径分歧。

## 运行模式

- **分离开发**：Linux 使用 `bash start.sh`，Windows 使用 `start.bat`。Vite 独立启动，将 API、上传、壁纸与看板路径代理到后端；开发后端设置 `SERVE_CLIENT=0`，不会误用旧构建。
- **仅后端部署**：使用 `bash deploy.sh --api-only`，或自行设置 `SERVE_CLIENT=0` 后从后端工程运行。后端仍提供 API、上传资源、健康检查与 `/dashboard`，不需要安装或构建前端。
- **兼容合并部署**：默认 `SERVE_CLIENT=1`，已有前端构建时由 Express 托管；不存在时显示后端状态页，而不是错误跳回自己。

后端默认只监听 `127.0.0.1`。需要局域网连接时必须明确配置 `HOST=0.0.0.0`，并先完成初始化。生产环境推荐 HTTPS 与反向代理，禁止直接把开发服务器开放到公网。

### 推荐的生产分离方式

前端构建可由 Nginx/CDN 静态层独立发布，应用服务器单独运行；在同一个公开站点来源下，将 `/api`、`/uploads`、`/rele`、`/dashboard` 转发到后端。这种方式分离了发布与运行进程，同时保留浏览器同源安全边界。

当前浏览器应用采用同源相对资源路径；这不代表“把前端域名与 API 域名任意拆开后只配置 CORS 就能完全兼容”。管理看板还使用限定路径的 HttpOnly、SameSite Cookie 与 CSRF 校验。若必须使用完全不同的公开域名，需要另外设计资源 URL、Cookie 与代理策略，不能简单设置通配 CORS。远程开发后端可通过 Vite 的服务端代理来源配置接入，不需要把后台地址或凭证编入浏览器包。

未知 API 返回 JSON 404；缺失脚本、图片和保留的后端路径不再返回状态为 200 的 SPA 首页。只有接受 HTML 的页面请求才使用 SPA 回退。前端可用与数据库可用是两回事，监控应查询 `/api/health`。

## 管理概览接口

- Vue 管理区使用 `GET /api/admin/overview`；版本化客户端使用 `GET /api/v1/admin/overview`，后者保留统一响应信封。
- 独立看板使用 `GET /dashboard/api/overview`，需要同源 HttpOnly 看板 Cookie；票据由现有前端管理入口或管理员 API 客户端通过受保护的会话接口交换，不提供默认账号或免认证入口。数据仍由相同的概览服务生成。
- `days` 仅支持 7、30、90，默认 7；`wall_id` 可显式指定单墙。全局查询不被当前墙头隐式缩小；同时给出墙参数与墙头时必须一致。
- 全局统计、墙级统计、各项待办和运行状态分别按现有权限判断。界面隐藏不是授权依据；失效账号、撤销权限与失效成员关系由服务端重新验证。
- 未获授权的可选指标为 `null`，不是 0。0 代表“有权查看且数量为零”；前端用“无查看权限”或破折号区分。
- 墙列表最多返回 100 项并提供截断标记；聚合范围最多 500 个候选墙，超过时要求选择单墙，防止无界查询阻塞单进程。

### 指标口径

1. 日趋势按服务器本地日历，与数据库 `datetime('now','localtime')` 存储口径一致；返回日期范围、时区和偏移量。生成时间使用 UTC ISO。浏览器应展示返回日期，而不是把无时区日期重新当 UTC 转换。
2. 总数与每日趋势来自**目前仍然存在的记录**，不是不可变事件账本。删除内容后历史创建量会变化；改变服务器时区也会影响口径，不应把当前数据解释为精确审计日志。
3. 成员数为有效成员关系数，跨墙相加不是去重用户数。全局用户计数只对具有对应用户/审核权限的未筛墙概览展示。
4. 待办只统计当前用户有权处理的业务，不能通过概览绕过举报、审批或反馈权限。
5. 近一小时访问量属于当前进程的内存窗口，重启清零，不等价于累计 PV、同时在线或登录活跃用户；概览轮询自身不计入。
6. 运行信息仅展示必要的内存、运行时长、数据库状态和访问汇总，不展示环境变量、密钥、磁盘绝对路径、IP、真实姓名、私信正文或匿名作者身份。

完整字段见 [移动 API 文档](MOBILE-API.md) 和 [OpenAPI 契约](openapi.json)。启动参数见 [启动说明](STARTUP.md)。

## 永久删除校园墙

管理后台的“所有校园墙”面板使用全局 `global.wall.manage` 权限，墙主身份本身不授予该能力。删除影响预览与最终删除均由服务端授权；最终操作要求精确墙名和操作者当前登录密码。预览反映读取时的数据，最终执行删除时会重新核对和统计，不锁定预览后的新增内容。

删除仅作用于目标墙及其关联业务记录。用户账号、好友、账号偏好、全局设置和其他墙的数据保留；删除最后一面墙也不移除初始化标记或重新开放首次设置。前端在成功后清理当前墙与权限缓存、作废旧墙列表请求，再重新获取有效上下文。

数据库清理在单个事务内完成，异常回滚；若投票记录与选项归属不一致（包括其他墙记录指向本墙选项，以及本墙记录指向其他投票或失效选项），返回 `409 WALL_REFERENCE_CONFLICT`，保留全部数据，避免外键级联越墙删除。当前上传文件未记录明确墙归属，因此本版不在删墙请求中物理删除附件：候选附件全部保留，`deletable_attachments` 为 0，需在独立存储清理流程中核对；确认界面和返回的 `warnings` 会说明此策略。删除数据库记录不代表擦除磁盘、历史备份或第三方副本。接口定义见 [移动 API](MOBILE-API.md)。

## 壁纸故障处理

默认从服务端获取必应图片并缓存，浏览器只加载受限的同源资源。服务端维持固定的上游来源、路径、大小和超时限制；网络读取与图片校验共享请求截止时间，元信息读取和完整解码共用有界处理队列，超时任务在实际结束前继续占用槽位，避免重复重试导致处理并发失控。元信息读取超时后不会再启动解码，也不会因此删除已存在的合法缓存。只读取图片元信息不足以证明 JPEG 完整：截断文件仍可能有合法尺寸，因此下载内容和复用的磁盘缓存均需要完整解码校验。

前端按“首选来源 → 本地接口 → 有限的随项目发布的本地资源”处理可恢复的加载故障，在解码成功后才替换当前图，并展示回退或不可用状态。切换来源、关闭壁纸或组件卸载会使旧请求和图片事件失效；关闭设置不会被回退逻辑覆盖。图片接口、图片文件和页面是否可见应分开验证，不能仅凭 API 返回 200 判断展示正常。

独立静态部署仍需正确代理 `/api` 与 `/rele`。更新后需重启后端并重新发布前端构建；测试环境能取到必应图片，不代表所有部署网络均可访问。

## 仍需遵守的部署限制

- sql.js 在一个 Node 进程内持有数据库并周期落盘。独立协调文件上的内核排他锁会拒绝同目录第二实例，防止互相覆盖；协调文件不保存业务数据或密钥，退出/崩溃后自动释放，不要主动删除或替换它。该机制要求本地可信文件系统，不保证 NFS/CIFS 语义。本次没有将其变成多实例数据库。
- 前后端更新需协调接口兼容，但不需要相互重装依赖。更新静态文件不等于更新后端进程；缺少新接口时必须重启后端。
- 生产备份、HTTPS、代理头覆盖、数据目录权限与恢复演练仍由运维负责。依赖审计通过不代表不存在所有业务漏洞。
